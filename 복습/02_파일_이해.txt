02. 선형회귀 — 여러 힌트로 숫자 맞히고, 처음 보는 문제로 시험 보기

1) 이번 파일의 이야기를 먼저 한 문장으로 읽어보자.

"센서 4개의 값을 보고 공정온도를 맞히는 방법을 연습한 다음,
연습할 때 쓰지 않은 데이터로 얼마나 잘 맞히는지 확인한다."

00에서는 재료인 데이터를 열어봤다.
01에서는 공기온도 하나로 공정온도를 맞히도록 w와 b를 조금씩 고쳤다.
02에서는 힌트를 4개로 늘리고, 연습 문제와 시험 문제를 따로 나눈다.
새로운 원리로 전부 바뀐 것이 아니라 01에서 하던 일을 확장한 것이다.

2) '선형회귀'와 '다변수'라는 이름은 어렵지만 하는 일은 단순하다.

회귀 = 온도처럼 숫자로 된 답을 맞히는 일.
선형 = 각 입력에 가중치를 곱한 다음, 모두 더하고 절편을 더하는 방식.
다변수 = 답을 맞힐 때 입력을 여러 개 쓰는 것.

이번 입력: 공기온도, 회전수, 토크, 공구마모.
이번 정답: 공정온도 하나.
입력이 4개라는 말이지 정답이 4개라는 말은 아니다.

3) import는 필요한 도구 상자를 꺼내는 문장이다.

import os             → 파일이 있는 위치를 다룰 도구
import numpy as np    → 여러 숫자를 한꺼번에 계산할 도구, 별명은 np
import pandas as pd   → 표를 읽고 다룰 도구, 별명은 pd

DATA는 데이터 폴더의 위치를 담은 이름이다.
__file__은 지금 실행하는 파이썬 파일을 가리킨다.
abspath는 전체 경로를 구하고, dirname은 그 파일이 있는 폴더를 구한다.
".."는 한 단계 위 폴더, join은 경로 조각들을 연결하는 도구다.
pd.read_csv(...)는 CSV 파일을 읽어서 df라는 표에 담는다.
encoding="utf-8-sig"는 파일의 글자를 읽는 방식을 지정한다.

4) 특징(feature)은 '정답을 맞히려고 사용하는 힌트'다.

특징이름 = ["공기온도", "회전수", "토크", "공구마모"]

대괄호 안에 이름 4개를 넣어 목록을 만들었다. 이런 목록을 리스트라고 한다.
df[특징이름]은 df에서 그 이름의 열 4개만 꺼내라는 뜻이다.

X = df[특징이름].values.astype(float)

.values        → pandas 표에서 NumPy 계산용 배열을 꺼낸다.
.astype(float) → 소수점이 있는 숫자로 계산할 수 있게 자료형을 바꾼다.
X              → 그렇게 꺼낸 입력 표를 담아두는 이름이다.

5) X는 문제의 힌트 모음이고, y는 실제 정답 모음이다.

y = df["공정온도"].values.astype(float)

첫 번째 기록을 예로 들면:
X[0] = [302.1, 1454.0, 47.3, 20.0]
y[0] = 313.2

"힌트 4개가 이 값들일 때, 실제 공정온도는 313.2였다"라는 한 쌍이다.
파이썬은 번호를 0부터 세므로 [0]이 첫 번째다.
코드에서는 각 행을 '설비 한 대'라고 부른다.
좀 더 일반적으로는 '센서값과 정답을 함께 기록한 사례 하나'라고 생각하면 된다.

6) shape는 숫자가 어떤 모양으로 담겼는지 알려준다.

X.shape → (200, 4): 기록 200개 × 힌트 4개인 표.
y.shape → (200,): 정답 숫자 200개가 담긴 한 줄 배열.

01의 x는 힌트가 하나라 (200,)이었다.
02의 X는 힌트가 네 개라 (200, 4)이다.
소문자 x와 대문자 X는 사람이 구별하기 쉽게 붙인 이름이다.
대문자를 쓴다고 자동으로 표가 되는 것은 아니다.

7) 왜 학습용과 시험용을 나눌까?

같은 문제집으로 공부하고 그 문제집으로만 시험을 보면,
새 문제도 잘 푸는지 확인하기 어렵다.
그래서 200개 중 140개로 배우고, 남은 60개로 시험을 본다.

train = 학습용. w와 b를 고칠 때 사용하는 데이터.
test  = 시험용. 배운 결과를 평가하는 데이터.
일반화 = 처음 보는 데이터에서도 잘 맞히는 능력.

공부한 문제를 다시 풀면 항상 만점인 것은 아니다.
다만 그 점수만으로 새로운 문제에 대한 실력을 판단하면 안 된다는 뜻이다.

8) rng = np.random.RandomState(42)는 섞기 도구를 준비한다.

42는 무작위 숫자를 만드는 시작 번호인 '시드'다.
같은 데이터로 이 코드 전체를 다시 실행하면 같은 순서로 섞여서
누가 실행하든 결과를 비교하기 편하다.
42에 특별히 잘 배우게 하는 능력이 있는 것은 아니다.
같은 rng로 연속해서 섞기 명령을 내리면 그때마다 순서는 달라질 수 있다.

순서 = rng.permutation(len(X))

len(X)는 행 개수인 200이다.
permutation은 0~199의 번호를 중복 없이 섞는다.
센서 숫자 하나하나를 뒤섞는 것이 아니라 '행을 고를 번호표'를 만든다.

9) n_train = int(len(X) * 0.7)은 공부할 문제 수를 정한다.

200 × 0.7 = 140.0
int(140.0) = 140

int는 여기서 소수 부분을 버리고 정수로 바꾼다.
70%인 140개를 공부하고, 30%인 60개를 시험에 쓴다.
7:3은 이번 예제의 선택이지 반드시 지켜야 하는 법칙은 아니다.

10) 콜론(:)은 '이 구간만 꺼내기'에 사용한다.

tr, te = 순서[:n_train], 순서[n_train:]

순서[:140] → 맨 앞부터 140번째 자리 직전까지, 총 140개.
순서[140:] → 140번 자리부터 끝까지, 총 60개.

tr에는 학습용 행 번호들이, te에는 시험용 행 번호들이 들어간다.
쉼표를 써서 두 이름에 각각 값을 담은 것이다.

11) 입력과 정답은 반드시 같은 번호로 골라야 한다.

X_train, X_test = X[tr], X[te]
y_train, y_test = y[tr], y[te]

예를 들어 tr이 [3, 0, 2]라면 입력도 3번, 0번, 2번 순서로 꺼내고,
정답도 3번, 0번, 2번 순서로 꺼낸다.
학생 이름표와 시험지를 함께 옮기는 것과 같다.
입력만 섞으면 다른 문제의 정답으로 공부하게 된다.

나눈 뒤 모양:
X_train: (140, 4)    y_train: (140,)
X_test:  (60, 4)     y_test:  (60,)

12) 표준화는 서로 다른 숫자의 눈금을 맞추는 일이다.

공기온도는 약 300, 회전수는 약 1500, 토크는 약 40처럼 크기가 다르다.
회전수가 큰 숫자라고 해서 공정온도 예측에 더 중요한 것은 아니다.
숫자 눈금 차이가 크면 하나의 학습률로 w들을 조절하기 어려워질 수 있다.

표준화 공식 = (값 - 평균) / 표준편차
평균은 가운데 기준, 표준편차는 숫자들이 얼마나 퍼졌는지 나타내는 눈금이다.

예를 들어 평균 300, 표준편차 2일 때:
302 → (302 - 300) / 2 = 1
300 → (300 - 300) / 2 = 0
298 → (298 - 300) / 2 = -1

1은 '평균보다 한 눈금 높음', -1은 '평균보다 한 눈금 낮음'이다.
값을 모두 같게 만드는 것이 아니라, 비교하고 계산할 눈금을 바꾸는 것이다.

13) axis=0은 각 열을 위에서 아래로 모아서 계산하라는 뜻이다.

mu = X_train.mean(axis=0)
sd = X_train.std(axis=0)

mu에는 센서별 평균 4개가 들어간다.
sd에는 센서별 표준편차 4개가 들어간다.
온도끼리 평균을 내고, 회전수끼리 평균을 내는 식이다.
axis=1이면 각 행에서 가로로 모아 계산한다.

Z_train = (X_train - mu) / sd

NumPy가 각 열에 맞는 평균을 빼고 표준편차로 나눠준다.
이처럼 크기가 다른 배열을 규칙에 맞춰 함께 계산하는 것을 브로드캐스팅이라고 한다.
Z는 표준화한 입력을 담은 이름이다. 행과 열 개수는 X와 같다.

14) 시험용도 반드시 학습용에서 만든 눈금으로 바꾼다.

Z_test = (X_test - mu) / sd

학습 때 정한 자로 시험 때도 재는 것이다.
시험용만 따로 평균과 표준편차를 구하면, 같은 실제 값도 다른 숫자로 바뀔 수 있다.
그러면 모델이 공부한 눈금과 시험 때 받는 눈금이 달라진다.
전체 데이터로 눈금을 미리 만들면 시험용 정보가 준비 과정에 들어가는
'데이터 누수'도 생기므로, 먼저 나누고 학습용으로만 눈금을 만든다.

학습용 Z의 열별 평균은 거의 0, 표준편차는 거의 1이 된다.
시험용 Z의 평균은 꼭 0일 필요가 없고 표준편차도 꼭 1일 필요가 없다.
새 데이터 한 건이 와도 저장해 둔 mu와 sd로 똑같이 바꿀 수 있다.
한 건만으로는 퍼진 정도를 제대로 정할 수 없기 때문이다.
참고로 한 열이 모두 같은 값이면 sd가 0이라 나누기 처리가 따로 필요하다.

15) 표준화하지 않고 걷는 코드는 '눈금이 다르면 얼마나 어려운가'를 보여준다.

for lr in [0.1, 0.0000001]:

학습률 0.1과 0.0000001을 각각 시험한다.
np.zeros(4)는 [0, 0, 0, 0]인 가중치를 만든다.
np.eye(4)[j]는 j번째 자리만 1이고 나머지는 0인 배열이다.
예를 들어 j=1이면 [0, 1, 0, 0]이다.
여기에 1e-4를 곱하면 두 번째 가중치만 0.0001 움직일 수 있다.

1e-4 = 0.0001, 2e-4 = 0.0002이다.
[계산식 for j in range(4)]는 j를 0, 1, 2, 3으로 바꿔 계산해 목록을 만든다.
np.array(...)는 그 목록을 NumPy 배열로 바꾼다.
즉, 긴 gw 식은 '가중치를 하나씩 살짝 움직여 기울기 4개를 구하기'다.

실행 결과 큰 학습률에서는 손실이 약 1.11 × 10의 39제곱으로 커졌다.
아주 작은 학습률에서는 20번 후에도 손실이 약 1110이었다.
이번 조건에서 둘 다 학습이 잘되지 않았다는 시연이다.
표준화하지 않으면 어떤 방법으로도 학습할 수 없다는 뜻은 아니다.

16) 예측식은 01의 손잡이를 4개로 늘린 모습이다.

01: 예측 = w × x + b
02: 예측 = w1 × z1 + w2 × z2 + w3 × z3 + w4 × z4 + b

z1~z4는 표준화한 센서값이고 w1~w4는 각 센서에 붙인 가중치다.
b는 마지막에 더하는 공통 보정값인 절편이다.
w 4개와 b 1개, 총 5개의 손잡이를 조절한다.

def 예측(Z, w, b):
    return Z @ w + b

def는 자주 할 일을 함수로 묶는 문법이고, return은 계산 결과를 돌려준다.
@는 여기서 '같은 자리끼리 곱한 다음 더하기'를 각 행마다 해준다.

설명용 예시:
센서값이 [1, 2, 0, -1], 가중치가 [2, 3, 4, 5], b가 10이라면
1×2 + 2×3 + 0×4 + (-1)×5 + 10 = 13이다.
Z에 140행이 있으면 이런 답을 140개 한꺼번에 만든다.

17) 손실은 01과 똑같이 '틀린 정도를 제곱한 것의 평균'이다.

np.mean((y - 예측(Z, w, b)) ** 2)

실제 정답에서 예측값을 뺀다 → 제곱한다 → 평균을 낸다.
** 2는 제곱, np.mean은 평균이다. 이 값을 MSE라고 한다.
작을수록 예측이 실제 값에 가깝고, 0이면 모든 예측이 맞았다.
단, 제곱한 오차라서 MSE 1.152를 '평균 1.152도 틀림'으로 읽으면 안 된다.

18) 기울기_밟아보기는 손잡이를 하나씩 움직여 방향을 알아본다.

h = 0.0001은 시험 삼아 움직여볼 아주 작은 거리다.
gw = np.zeros(len(w))는 가중치 기울기를 담을 빈칸 4개를 만든다.

w_plus, w_minus = w.copy(), w.copy()

.copy()는 원본과 별개로 바꿀 수 있는 복사본을 만든다.
원래 w를 유지한 채 오른쪽과 왼쪽을 시험해보려는 것이다.

w_plus[j] += h  → j번째 가중치에 h를 더한다.
w_minus[j] -= h → j번째 가중치에서 h를 뺀다.
다른 가중치는 그대로 둔다.

기울기 ≈ (오른쪽 손실 - 왼쪽 손실) / (2 × h)

오른쪽과 왼쪽 사이 거리가 2h여서 2h로 나눈다.
기울기가 양수면 가중치를 줄이는 쪽이, 음수면 늘리는 쪽이 내리막 방향이다.
이렇게 작은 차이로 미분을 근사하는 방법을 수치미분이라고 한다.
gb는 똑같은 방법으로 b의 기울기를 구한 값이다.
손잡이는 5개지만, 각 손잡이의 양쪽을 보므로 한 번에 손실을 10번 계산한다.

19) 학습 함수는 '방향 확인 → 조금 고치기'를 반복한다.

def 학습(Z, y, lr=0.1, epochs=500):

lr은 한 번에 고치는 크기를 조절하는 학습률이다.
epochs는 반복 횟수이고, 따로 지정하지 않으면 500이다.
Z.shape[1]은 열 개수다. 센서가 4개면 가중치도 4개를 만든다.
for _ in range(epochs)는 지정한 횟수만큼 반복한다.
_는 여기서 '몇 번째 반복인지 숫자 자체는 쓰지 않겠다'는 관례적인 이름이다.

w = w - lr * gw
b = b - lr * gb

기울기의 반대 방향으로 조금씩 움직여 손실을 줄이는 경사하강법이다.
w가 배열이므로 가중치 4개가 각자의 기울기에 따라 함께 바뀐다.

w, b = 학습(Z_train, y_train)

학습용 입력과 정답만 주고, 배운 가중치와 절편을 돌려받는다.
이 학습 함수에는 시험용 정답을 넣지 않는다.

모든 센서가 학습용 평균값이면 z들이 모두 0이므로 예측은 b가 된다.

21) zip은 두 목록을 순서대로 짝지어준다.

for 이름, wi in zip(특징이름, w):

첫 이름인 공기온도와 첫 가중치, 두 번째 이름인 회전수와 두 번째 가중치를
차례로 묶어서 이름과 wi에 담아 반복한다.

f"{이름:6s} w = {wi:+.3f}"

f 문자열은 중괄호에 담긴 값을 글 속에 넣는다.
6s는 글자를 최소 6칸 폭에 표시하고, +.3f는 부호와 소수점 아래 3자리를 표시한다.
예측이나 학습을 바꾸는 기능이 아니라 출력 모양을 정하는 문법이다.

22) 채점할 때는 학습을 다시 하지 않고 배운 w와 b를 그대로 쓴다.

tr_pred = 예측(Z_train, w, b)
te_pred = 예측(Z_test, w, b)

tr_pred는 공부했던 문제의 예측 답안이다.
te_pred는 처음 보는 시험 문제의 예측 답안이다.
각 답안을 해당 실제 정답과 비교해 MSE와 R²를 구한다.

23) R²는 '평균만 답하는 방법보다 얼마나 나은가'를 보여준다.

R² = 1 - 모델의 제곱오차 합 / 평균만 답했을 때의 제곱오차 합

코드의 np.sum은 모두 더하기, y.mean()은 채점하는 정답들의 평균이다.
R²가 1이면 완벽하게 맞혔다.
R²가 0이면 그 정답들의 평균만 답한 것과 제곱오차 합이 같다.
R²가 음수면 그 평균만 답하는 것보다도 오차가 크다.

R² 0.78은 '100문제 중 78문제를 맞혔다'는 정답률이 아니다.
평균만 답하는 기준보다 제곱오차 합이 약 78% 줄었다는 뜻이다.
참고로 정답이 전부 같으면 분모가 0이어서 이 함수로는 정상 계산할 수 없다.

24) 이번 실제 점수는 이렇게 나왔다.

학습용 140개: R² 0.8079, MSE 0.781
시험용  60개: R² 0.7800, MSE 1.152

공부한 문제와 처음 보는 문제에서 비슷한 수준으로 맞혔다.
이번 분할에서는 학습용에만 치우친 큰 성능 차이가 보이지 않는다.
하지만 점수가 비슷하다는 사실 하나로 현장에서도 반드시 잘된다고 보장할 수는 없다.
시험용 점수가 학습용보다 조금 더 높게 나오는 경우도 있다.

te_pred[:6]과 y_test[:6]은 시험용 앞 6개의 예측과 실제 값을 꺼낸다.
t - p는 실제 값에서 예측값을 뺀 차이다.
양수라면 예측이 실제보다 낮았고, 음수라면 예측이 실제보다 높았다.

25) 과적합은 '연습 문제에는 잘 맞는데 새 문제에는 약한 상태'다.

w5, b5 = 학습(Z_train[:5], y_train[:5], epochs=2000)

학습용 앞 5개만 주고 2000번 반복해서 배우게 한다.
결과는 학습용 5개 R² 약 1.0000, 시험용 60개 R² 0.6843이었다.
140개로 공부했을 때의 시험용 0.7800보다 낮아졌다.

딱 5개의 사례 안에서 우연히 보인 모습까지 맞추다 보니
새 사례에 적용할 규칙이 덜 좋아진 것이다. 이를 '외웠다'고 비유한다.
컴퓨터가 답안지를 별도로 저장했다는 뜻은 아니다.
손잡이가 5개이고 사례가 5개라고 항상 만점이 보장되는 것도 아니다.

26) 과소적합은 '학습용에서도 규칙을 충분히 잡지 못한 상태'다.

중요한 힌트가 빠졌거나, 모델이 너무 단순하거나, 학습이 부족할 수 있다.
원인에 따라 중요한 입력을 넣거나 모델·학습 방법을 바꿔야 한다.
무조건 반복 횟수만 늘린다고 해결되지는 않는다.

학습용은 좋은데 시험용이 크게 나쁨 → 과적합 등을 의심한다.
둘 다 나쁨 → 과소적합이나 입력 정보 부족 등을 살펴본다.
둘 다 좋고 비슷함 → 새 데이터에도 잘 맞을 가능성을 보여준다.
점수 차이가 0.05 또는 0.10이라는 숫자는 보편적인 판정 기준이 아니다.

27) 가중치 순위 코드는 부호를 떼고 크기가 큰 순서로 줄 세운다.

sorted(zip(특징이름, w), key=lambda t: -abs(t[1]))

zip(...) → 센서 이름과 가중치를 짝짓는다.
t        → 그중 한 쌍, 예를 들면 ("토크", -0.109)이다.
t[1]     → 그 쌍에서 두 번째인 가중치를 꺼낸다.
abs(...) → 부호를 뺀 크기를 구한다. abs(-0.109)는 0.109다.
lambda   → 정렬에 사용할 짧은 계산 규칙을 만든다.
sorted   → 그 규칙으로 순서를 정한다.

sorted는 기본적으로 작은 값부터 놓는다.
앞에 마이너스를 붙이면 큰 절댓값일수록 더 작은 음수가 되어 앞에 온다.
이번에는 공기온도, 토크, 공구마모, 회전수 순서가 된다.

'높을수록 공정온도 ↑' if wi > 0 else '높을수록 공정온도 ↓'
이 문법은 wi가 양수이면 앞 문구, 아니면 뒤 문구를 고른다.
정확히 0이면 영향이 없지만, 이 코드에서는 else 쪽 문구가 표시된다.

28) 큰 가중치는 '이 모델에서 눈여겨볼 힌트'이지 원인의 증거는 아니다.

표준화했으므로 센서가 각각 한 표준편차 변할 때의 예측 변화량을 비교할 수 있다.
다만 비슷한 정보를 주는 센서끼리는 역할을 나눠 가지기도 한다.
가중치가 작다고 그 센서가 모든 상황에서 쓸모없는 것은 아니다.

이번 결과는 '이 데이터로 학습한 이 선형모델은 공기온도를 크게 활용한다'로 읽자.
'실제 공정온도는 공기온도 하나로만 결정된다'고 단정하면 안 된다.
가중치의 방향도 다른 입력들을 고정했을 때 모델 예측이 움직이는 방향이다.

29) 센서를 하나씩 빼는 실험은 '힌트가 없어지면 얼마나 어려워질까?'를 본다.

for 뺄 in range(4):
    남길 = [j for j in range(4) if j != 뺄]

range(4)는 0, 1, 2, 3이다.
!=는 '같지 않다'라는 뜻이다.
뺄이 1이면 남길은 [0, 2, 3]이다. 회전수 열을 빼는 것이다.

Z_train[:, 남길]

쉼표 앞 :는 모든 행을, 쉼표 뒤 남길은 선택한 열들을 뜻한다.
그 입력으로 학습을 다시 해서 가중치 3개와 절편을 새로 구한다.
w_, b_는 새 결과를 담는 이름이다. 끝의 밑줄에 특별한 계산 기능은 없다.

공기온도를 빼면 학습용 R² 0.0463, 시험용 R² -0.0020이었다.
평균만 답하는 수준에 가까워졌다. 중요한 힌트가 빠진 모습을 보여준다.
나머지 센서를 하나씩 뺄 때는 시험용 점수가 거의 유지되었다.

30) 시험 점수를 보며 계속 고르면 시험지도 연습 문제처럼 된다.

이 파일에서는 원리를 보여주려고 여러 실험 결과를 같은 시험용으로 비교한다.
실제로 센서나 학습 방법을 고를 때는 학습 데이터 안에서 검증용을 따로 두고,
마지막 시험용은 선택이 끝난 뒤 최종 평가에 쓴다.

학습용 = 공부할 문제.
검증용 = 공부 방법을 고르는 중간 점검 문제.
시험용 = 모든 선택을 끝내고 실력을 확인할 마지막 문제.

5개·20개 실험도 표준화 눈금은 처음 학습용 140개로 만든 것을 재사용한다.
따라서 '모든 준비까지 오직 5개·20개로만 했다'는 실험은 아니다.
w와 b를 배우는 사례 수를 줄여 차이를 보여주는 시연으로 이해하면 된다.

31) 마지막 20개 실습의 결과도 함께 읽어보자.

w20, b20 = 학습(Z_train[:20], y_train[:20], epochs=2000)

학습 사례 수    그 사례들의 학습 R²    같은 시험용 60개의 R²
5개            1.0000                 0.6843
20개           0.8574                 0.7736
140개          0.8079                 0.7800

20개로 공부하면 5개일 때보다 연습 점수는 내려갔지만 시험 점수는 올라갔다.
연습 문제 만점이 최종 목표가 아니라 새 문제를 잘 맞히는 것이 목표다.
이것은 이번 데이터에서 나온 결과이며, 데이터 수를 늘릴 때마다
시험 점수가 반드시 올라간다는 법칙은 아니다. 반복 횟수도 실험별로 다르다.

32) 원본 주석을 읽을 때 헷갈리지 말아야 할 부분도 있다.

① '01에서 한 줄 (200, 4)'이라는 주석과 달리 01의 x는 (200,)이다.
② 예측식 주석의 두 번째 w1은 w2로 읽어야 한다.
③ 작은 학습률은 실제 코드 기준 0.0000001이다. 일부 주석의 0.000001과 다르다.
④ 시험용 표준화 평균은 0일 필요가 없다는 뜻이지, 절대로 0일 수 없다는 뜻은 아니다.
⑤ 데이터를 항상 섞는 것도 정답은 아니다. 미래를 예측하는 문제라면
   과거로 배우고 미래로 시험하도록 시간순으로 나눌 필요가 있다.
   같은 설비의 반복 기록이 많다면 설비별로 나누는 방법도 고려한다.
