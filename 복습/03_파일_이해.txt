5) 고장이 몇 개 있는지 먼저 센다

y.sum()은 정답을 모두 더한다.
정상 0은 더해도 그대로이고 고장 1만 개수를 늘리므로 고장 개수가 된다.
예: [0, 1, 0, 1, 0]의 합은 2 → 고장 2개.
y.mean()은 고장 개수 / 전체 개수이므로 고장 비율이다.

실제 데이터: 전체 200개, 고장 8개, 정상 192개.
고장 비율은 8 / 200 = 0.04 = 4%다.
f'{y.mean():.1%}'는 그 비율을 4.0%처럼 표시한다.
len(y)는 전체 개수, int(y.sum())은 개수를 정수로 표시하기 위한 변환이다.

6) 불균형 데이터는 한쪽 종류가 훨씬 많은 데이터다

상자에 정상 카드 192장과 고장 카드 8장이 있다고 생각해보자.
카드를 보지도 않고 매번 '정상!'이라고 말해도 200장 중 192장을 맞힌다.
정확도는 96%지만 고장 카드는 한 장도 찾아내지 못했다.

그래서 이번 파일은 단순히 '몇 개를 맞혔나?'뿐 아니라
'정말 찾아야 하는 고장을 몇 개나 찾았나?'를 함께 살펴본다.

7) 고장 사례와 정상 사례를 따로 살펴본다

df[df.고장여부 == 1]['공구마모'].mean()

df.고장여부는 여기서 df['고장여부']와 같은 열을 가리킨다.
== 1은 '값이 1과 같은가?'라는 질문이다.
df[조건]은 조건에 맞는 행만 남긴다.
그중 공구마모 열을 꺼내 평균을 구한다.

실제 출력에서 평균 공구마모는 고장 223.9, 정상 112.9였다.
평균 토크는 고장 46.1, 정상 40.6이었다.
round(값, 1)은 소수점 아래 한 자리로 반올림한다.
이 차이는 배울 힌트지만, 마모가 크면 무조건 고장이라는 법칙은 아니다.
이 부분은 전체 데이터를 살펴보는 수업용 탐색이다.
실제 모델을 개발할 때는 시험용을 먼저 떼어두고 학습용을 중심으로 탐색하는 편이 좋다.

8) 고장 사례를 양쪽에 나누어 넣는 이유

02에서는 모든 행 번호를 한꺼번에 섞었다.
이번에는 고장 사례가 8개뿐이라 무작위 분할에 따라 시험용에 고장이 없을 수도 있다.
그러면 정확도는 계산할 수 있어도 고장을 찾아내는 능력을 시험할 수 없다.
그래서 고장끼리, 정상끼리 따로 섞은 다음 양쪽에 나눠 담는다.
이처럼 종류별 비율을 고려해 나누는 방법을 층화 분할이라고 한다.

9) np.where는 조건에 맞는 위치를 찾는다

고장idx = rng.permutation(np.where(y == 1)[0])

예를 들어 y = [0, 1, 0, 0, 1]이면
y == 1은 [False, True, False, False, True]가 된다.
np.where(y == 1)[0]은 [1, 4], 즉 고장이 있는 행 번호 배열이다.
여기의 [0]은 첫 고장 하나만 고르는 것이 아니다.
np.where가 묶어서 돌려준 결과 중 '위치 배열'을 꺼내는 것이다.
permutation은 그 행 번호들을 무작위로 섞는다.
정상idx도 같은 방식으로 정상이 있는 행 번호를 섞는다.

rng = np.random.RandomState(3)의 3은 무작위 시작 번호인 시드다.
같은 데이터로 코드 전체를 다시 실행했을 때 같은 분할을 얻도록 정했다.
3이라는 번호 자체가 학습 성능을 좋게 만드는 것은 아니다.

10) 섞은 번호들을 이어 붙여 학습용과 시험용을 만든다

tr = np.concatenate([고장idx[:6], 정상idx[:134]])
te = np.concatenate([고장idx[6:], 정상idx[134:]])

[:6]은 앞 6개, [6:]은 6번 자리부터 끝까지다.
concatenate는 두 배열을 하나로 이어 붙이는 도구다.
학습용: 고장 6개 + 정상 134개 = 140개.
시험용: 고장 2개 + 정상 58개 = 60개.

전체는 7:3이지만 고장 8개를 정확히 7:3으로 나눌 수는 없다.
사례를 쪼갤 수 없으니 고장은 6개와 2개로 나눈 것이다.
6과 134는 현재 데이터에 맞춰 직접 적은 수다. 파일이 바뀌면 확인이 필요하다.

11) 문제와 정답은 같은 번호로 꺼낸다

X_train, X_test, y_train, y_test = X[tr], X[te], y[tr], y[te]

학습용 번호가 17번이면 X의 17번 센서값과 y의 17번 정답을 함께 가져온다.
서로 다른 번호로 고르면 문제와 답안지가 뒤바뀐다.

12) 표준화는 02와 같은 이유로 한다

mu, sd = X_train.mean(axis=0), X_train.std(axis=0)
Z_train = (X_train - mu) / sd
Z_test = (X_test - mu) / sd

회전수 약 1500과 토크 약 40은 숫자 크기가 다르다.
각 센서값을 '평균에서 몇 눈금 떨어져 있나?'로 바꾸면
가중치를 고칠 때 눈금 차이 때문에 생기는 어려움을 줄일 수 있다.
axis=0은 각 열을 세로로 모아서 계산하라는 뜻이다.
mu와 sd에는 각각 센서별 평균 4개와 표준편차 4개가 들어간다.

시험용에도 학습용에서 만든 눈금을 쓴다. 시험용만 새 자를 만들지 않는다.
정답 y는 0과 1 그대로 두고, 입력 X만 Z로 바꾼다.
어떤 열의 표준편차가 0이라면 나누기 전에 별도 처리가 필요하다.

13) 가중치를 곱하고 더한 결과는 아직 확률이 아니다

점수 = Z @ w + b

02에서 익힌 계산이다. 센서별로 가중치를 곱한 다음 모두 더하고 b를 더한다.
@는 여기서 각 행의 센서값과 가중치를 같은 자리끼리 곱해 더하는 계산이다.
결과는 -5도 되고 2도 되고 10도 될 수 있다.
하지만 확률은 0에서 1 사이로 표현해야 한다.
그래서 숫자 점수를 확률로 바꾸는 장치가 하나 필요하다.

14) 시그모이드는 숫자 점수를 0과 1 사이로 바꾼다

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def는 함수를 정의하는 문법이고 return은 계산 결과를 돌려준다.
np.exp(x)는 약 2.718인 수 e를 x제곱한 값이다.
지금은 수식 암기보다 입력과 출력의 관계를 이해하면 충분하다.

입력 점수 -5 → 약 0.007
입력 점수 -2 → 약 0.119
입력 점수  0 → 0.500
입력 점수  2 → 약 0.881
입력 점수  5 → 약 0.993

점수가 낮으면 0에 가까워지고 높으면 1에 가까워진다.
0이면 정확히 0.5가 된다. 곡선 모양이 S자처럼 생겼다.
수학적으로 유한한 입력의 결과는 0보다 크고 1보다 작다.

15) 확률 함수는 계산 두 개를 연결한다

def 확률(Z, w, b):
    return sigmoid(Z @ w + b)

먼저 센서값으로 점수를 만든다 → 시그모이드로 바꾼다.
시험용이 60행이면 고장 확률 추정값도 60개 나온다.
0.8이면 모델은 '고장일 확률이 80%쯤'이라고 추정한 것이다.
실제로 반드시 80%만큼 정확하다고 보장되는 것은 아니다.
모델이 데이터에서 배운 추정값이기 때문이다.

이 함수의 z는 시그모이드에 넣는 숫자 점수다.
Z_train의 Z는 표준화한 입력 표다. 둘을 같은 것으로 생각하지 말자.

16) 확률과 판정과 실제 정답을 구별하자

실제 정답 y = 1       → 데이터에 기록된 실제 상태는 고장.
예측 확률 p = 0.232   → 모델이 추정한 고장 가능성은 약 23.2%.
최종 판정 = 0        → 기준 0.5보다 낮아서 정상으로 분류.

확률은 모델이 계산한 값이고, 판정은 그 확률에 기준을 적용한 결과다.
y는 둘을 평가할 때 비교하는 실제 정답이다.
고장 가능성이 23.2%라고 판단한 사례도 실제로는 고장일 수 있다.

17) 로그손실은 확률 답안에 벌점을 주는 방법이다

정답이 고장일 때 모델이 고장 확률 0.99라고 하면 정답에 잘 맞는 예측이다.
반대로 고장 확률 0.01이라고 하면 '거의 정상일 거야'라고 자신 있게 틀린 것이다.
후자에 훨씬 큰 벌점을 주어 모델을 고친다.

정답이 고장일 때 벌점 = -np.log(p)
고장 확률 0.99 → 벌점 약 0.010
고장 확률 0.50 → 벌점 약 0.693
고장 확률 0.01 → 벌점 약 4.605

np.log는 자연로그를 계산한다. 여기서는 앞의 마이너스까지 합쳐
'정답에 준 확률이 낮을수록 벌점이 커진다'고 이해하자.
정답이 정상이면 정상 확률인 1-p를 사용해서 -np.log(1-p)로 벌점을 준다.
각 사례의 벌점을 평균 낸 것이 로그손실, 또는 이진 교차 엔트로피다.

18) 긴 손실 수식은 정답에 따라 한쪽만 남는다

return -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))

y가 1이면 1-y는 0이므로 뒤쪽이 사라진다 → -log(p).
y가 0이면 앞쪽이 사라진다 → -log(1-p).
두 종류의 정답에 쓸 규칙을 한 줄에 넣은 것이다.
np.mean은 사례 전체의 평균을 구한다.

MSE는 온도 예측에서 쓰던 자이고, 여기서는 로그손실로 배운다.
분류 확률에 MSE를 절대로 쓸 수 없다는 뜻은 아니다.
이번 로지스틱 회귀 학습에서는 로그손실을 사용하는 것이다.

19) np.clip은 계산이 곤란한 끝값을 살짝 안으로 옮긴다

p = np.clip(확률(Z, w, b), 1e-12, 1 - 1e-12)

np.clip(값, 최소, 최대)는 최소보다 작으면 최소로,
최대보다 크면 최대로 바꾸고 범위 안의 값은 그대로 둔다.
1e-12는 0.000000000001이라는 아주 작은 수다.
컴퓨터 계산에서 확률이 0이나 1로 반올림되면 log(0) 문제가 생길 수 있다.
그래서 손실을 계산할 때만 양쪽 끝을 아주 조금 피한다.
정답을 바꾸거나 데이터를 삭제하는 작업이 아니다.

20) 기울기를 찾는 방법은 02와 같다

h = 0.0001
gw = np.zeros(len(w))

h는 시험 삼아 움직여볼 거리다.
gw는 가중치별 기울기를 담을 빈칸이다. 가중치 4개라 빈칸도 4개다.

w1, w2 = w.copy(), w.copy()
w1[j] += h
w2[j] -= h

원래 w는 유지한 채 복사본 두 개를 만든다.
j번째 가중치만 한쪽에서는 조금 키우고 다른 쪽에서는 조금 줄인다.
여기서 w1과 w2는 각각 가중치 4개가 담긴 배열이다.
'첫 센서 가중치 하나'와 '둘째 센서 가중치 하나'라는 뜻이 아니다.

gw[j] = (손실(Z, y, w1, b) - 손실(Z, y, w2, b)) / (2 * h)

오른쪽 벌점과 왼쪽 벌점 차이를 두 위치 사이 거리로 나눈다.
이렇게 기울기를 근사하는 방법이 수치미분이다.
gb도 b를 조금 늘리고 줄여 같은 방법으로 구한다.
가중치 4개와 절편 1개, 총 5개의 방향을 알아본다.

21) 학습은 벌점을 줄이는 방향으로 손잡이를 고치는 반복이다

def 학습(Z, y, lr=0.5, epochs=2000, 보여주기=True):

lr은 한 번에 얼마나 고칠지 정하는 학습률이다.
epochs는 반복 횟수다. 여기서는 기본 2000번이다.
보여주기는 중간 손실을 출력할지 정하는 스위치다.
True는 켬, False는 끔으로 생각하면 된다.

w = np.zeros(Z.shape[1])는 열 수만큼 가중치를 0으로 만든다.
b도 0으로 시작한다. 처음에는 모든 점수가 0이라 확률이 모두 0.5다.
for epoch in range(epochs)는 epoch를 0~1999로 바꾸며 반복한다.

w = w - lr * gw
b = b - lr * gb

기울기의 반대 방향으로 조금 움직여 손실을 줄이려는 경사하강법이다.
기울기를 구하는 데 쓰는 손실이 로그손실로 바뀌었을 뿐이다.
이 코드의 학습률과 반복 횟수가 모든 분류 문제의 정답은 아니다.

22) 중간 출력 문법을 읽어보자

if 보여주기 and epoch % 400 == 0:

if는 조건이 맞을 때만 아래 들여쓴 코드를 실행한다.
and는 두 조건이 모두 참이어야 한다는 뜻이다.
%는 나눗셈의 나머지를 구한다.
epoch가 0, 400, 800, 1200, 1600일 때 400으로 나눈 나머지가 0이다.
그래서 보여주기가 True이면 이 번호에서 손실을 출력한다.
epoch 0 출력도 w와 b를 한 번 수정한 뒤의 값이다.

f'{epoch:4d}'는 정수를 최소 4칸 폭으로,
f'{손실값:.4f}'는 숫자를 소수점 아래 4자리로 보여준다.
출력 모양을 정하는 것이지 학습 원리를 바꾸는 문법은 아니다.

23) 실제 학습 결과는 어떻게 나왔나

w, b = 학습(Z_train, y_train)

학습용 입력과 정답만 사용해서 가중치와 절편을 구한다.
출력된 손실은 0.5933 → 0.1180 → 0.1161 → 0.1158 → 0.1157이었다.
학습용에서 벌점이 줄어들고 있음을 보여준다.
그러나 이것만으로 시험용의 고장을 잘 찾는다고 보장되지는 않는다.

표준화 눈금의 가중치:
공구마모 +2.367 / 회전수 +0.566 / 공기온도 -0.427 / 토크 +0.239

다른 센서를 그대로 둘 때, 양의 가중치 센서가 커지면 점수와 고장 확률이 올라간다.
음의 가중치 센서가 커지면 점수와 고장 확률이 내려간다.
공구마모 한 표준편차 증가가 '확률 2.367 증가'라는 뜻은 아니다.
2.367은 시그모이드에 넣기 전 점수의 증가량이다.
확률의 변화량은 원래 점수가 어느 위치였는지에 따라 달라진다.
학습용 고장이 6개뿐이므로 가중치를 실제 고장 원인으로 단정하면 안 된다.

24) 가중치 순위를 만드는 문법은 02와 같다

sorted(zip(특징이름, w), key=lambda t: -abs(t[1]))

zip은 센서 이름과 가중치를 순서대로 짝짓는다.
t는 그중 한 쌍이고 t[1]은 두 번째 값인 가중치다.
abs는 부호를 뺀 크기를 구한다.
lambda는 정렬에 사용할 짧은 계산 규칙을 만든다.
sorted는 작은 값부터 정렬하므로 마이너스를 붙여 절댓값이 큰 것을 앞에 놓는다.

'클수록 고장 확률 ↑' if wi > 0 else '클수록 고장 확률 ↓'
wi가 양수이면 앞 문구를, 아니면 뒤 문구를 고른다.
정확히 0이면 실제로는 영향이 없지만 이 코드에서는 뒤 문구가 표시된다.

25) 임계값은 확률을 판정으로 바꾸는 기준선이다

p_test = 확률(Z_test, w, b)
판정 = (p_test >= 0.5).astype(int)

>=는 '크거나 같다'다.
0.5 이상이면 True, 미만이면 False가 된다.
.astype(int)는 True를 1로, False를 0으로 바꾼다.

확률 [0.8, 0.3, 0.5] → 비교 [True, False, True] → 판정 [1, 0, 1]
0.5도 기준에 포함되므로 고장 판정이다.
0.5는 이번에 시작한 기준이지 반드시 지켜야 하는 법칙은 아니다.

26) 고장 확률이 높은 순서로 줄 세운다

순위 = np.argsort(-p_test)

argsort는 정렬한 값 자체가 아니라 그 값들의 위치 번호를 돌려준다.
예를 들어 p_test = [0.2, 0.8, 0.1]이면 높은 순서의 번호는 [1, 0, 2]다.
마이너스를 붙여 높은 확률부터 오도록 만든 것이다.

for i in 순위[:8]:

상위 8개 번호를 차례로 i에 담는다.
p_test[i], 판정[i], y_test[i]를 함께 출력하므로 예측과 실제를 비교할 수 있다.
이번 결과에서 실제 고장 두 개의 확률은 약 0.528과 0.232였다.
기준이 0.5라서 첫 번째는 잡았고 두 번째는 놓쳤다.

27) 정확도는 전체 중 맞힌 비율이다

정확도 = np.mean(판정 == y_test)

==는 판정과 실제 정답이 같은지 비교한다.
같으면 True, 다르면 False이고 평균 계산에서는 1과 0처럼 계산된다.
따라서 맞은 개수 / 전체 개수가 된다.

이번에는 정상 58개를 모두 맞히고 고장 2개 중 1개를 맞혔다.
59 / 60 ≈ 0.9833 → 정확도 약 98.3%.
매우 높아 보이지만 실제 고장의 절반은 놓쳤다.

28) 혼동행렬은 결과를 네 종류로 나눈 표다

실제 고장 + 고장 판정 = TP → 고장을 잘 찾음
실제 고장 + 정상 판정 = FN → 고장을 놓침
실제 정상 + 고장 판정 = FP → 헛경보
실제 정상 + 정상 판정 = TN → 정상을 잘 통과시킴

P는 고장이라고 판정했다는 뜻, N은 정상이라고 판정했다는 뜻이다.
T는 판정이 맞음, F는 판정이 틀림이다.
우선 영어를 외우기보다 '잡음, 놓침, 헛경보, 정상 통과'로 읽자.
여기서 '잡음'은 소음이 아니라 '고장을 잡았다'는 뜻이다.

이번 기준 0.5의 결과: TP 1, FN 1, FP 0, TN 58.
네 개를 더하면 시험용 전체 60개가 된다.

29) 네칸 함수는 조건 두 개를 동시에 검사한다

TP = int(((y == 1) & (판정 == 1)).sum())

(y == 1)은 실제로 고장인가를 묻는다.
(판정 == 1)은 모델도 고장이라고 했는가를 묻는다.
&는 배열에서 같은 자리의 두 조건이 모두 참인지 확인한다.
.sum()으로 True의 개수를 센 다음 int로 정수로 만든다.
FN, FP, TN도 실제와 판정 조건을 바꾸어 같은 방법으로 센다.

return TP, FN, FP, TN은 숫자 네 개를 그 순서대로 돌려준다.
받을 때도 TP, FN, FP, TN = 네칸(...)처럼 순서를 맞춰야 한다.
배열 조건을 묶을 때는 코드처럼 각각 괄호로 감싸는 것을 기억하자.

30) 재현율은 실제 고장 중 얼마나 찾았는가다

재현율 = TP / (TP + FN)

분모 TP + FN은 실제 고장 전체다.
이번에는 실제 고장 2개 중 1개를 찾았으므로 1 / 2 = 0.5 = 50%다.
'진짜 고장들을 얼마나 놓치지 않았나?'를 보는 점수다.

TP / (TP + FN) if TP + FN else 0

분모가 0이 아니면 나누고, 0이면 대신 0을 넣으라는 뜻이다.
실제 고장이 하나도 없으면 이 재현율은 원래 정의할 수 없다.
이 코드에서는 0으로 나누는 오류를 피하려고 0을 대신 표시한다.

31) 정밀도는 고장 경보 중 얼마나 진짜인가다

정밀도 = TP / (TP + FP)

분모 TP + FP는 고장이라고 판정한 전체다.
이번에는 경보를 1개 냈고 그것이 진짜 고장이므로 1 / 1 = 1 = 100%다.
'경보가 울렸을 때 얼마나 믿을 만한가?'를 보는 점수다.

재현율은 실제 고장 목록을 기준으로 센다.
정밀도는 모델이 낸 고장 경보 목록을 기준으로 센다.
이번 정밀도가 100%여도 고장을 전부 찾은 것은 아니다.
경보가 하나도 없으면 정밀도 역시 정의할 수 없어서 이 코드는 0으로 대신 표시한다.

32) 아무것도 배우지 않고 전부 정상이라고 하면

게으른판정 = np.zeros_like(y_test, dtype=int)

zeros_like는 y_test와 같은 모양으로 0을 채운 배열을 만든다.
dtype=int는 정수로 만들라는 뜻이다.
정상 58개는 맞히고 고장 2개는 모두 놓친다.
정확도는 58 / 60 ≈ 96.7%, 재현율은 0%다.

우리 모델: 정확도 98.3%, 재현율 50%.
전부 정상: 정확도 96.7%, 재현율 0%.

정확도가 거짓 숫자인 것은 아니다. 전체를 맞힌 비율은 정확히 알려준다.
다만 고장을 찾는 목적에는 그 숫자 하나만으로 충분하지 않다는 뜻이다.

33) 기준선을 내리면 어떤 일이 생길까

0.232라는 확률은 기준 0.5에서는 정상 판정이다.
기준을 0.2로 낮추면 고장 판정으로 바뀐다.
이렇게 조금만 의심스러워도 경보를 울리면 고장을 더 잡을 수 있다.
대신 정상에게도 경보를 울릴 수 있다.

기준    잡음 TP    놓침 FN    헛경보 FP    재현율    정밀도
0.5     1          1          0            0.50      1.00

0.2     2          0          5            1.00      0.29
0.1     2          0          7            1.00      0.22

고장을 놓치는 비용과 헛경보로 검사하거나 멈추는 비용을 함께 고려해야 한다.
어느 쪽이 더 중요한지는 상황에 따라 다르다.

34) 임계값을 바꿀 때는 다시 학습하지 않는다

for th in [0.5, 0.3, 0.2, 0.1]:
    판정_th = (p_test >= th).astype(int)

th에 기준값을 하나씩 넣어 반복한다.
이미 구해둔 확률 p_test는 그대로다. w와 b도 그대로다.
바뀌는 것은 '어느 확률부터 고장으로 부를까?'라는 규칙뿐이다.
네칸 함수로 각 기준의 TP, FN, FP, TN을 다시 세고 재현율과 정밀도를 구한다.
출력의 ^4는 최소 4칸 안에 가운데 정렬하라는 뜻이다.

02의 센서 빼기: 입력 재료가 달라지므로 다시 학습했다.
03의 임계값 바꾸기: 같은 확률의 판정 기준만 바꾸므로 다시 학습하지 않는다.

35) 마지막 실습에서 0.15로 낮추면

37) 원본 주석에서 너무 단정적으로 읽지 말아야 할 내용

로지스틱 회귀는 일반적으로 반복 계산으로 학습하지만 경사하강 외의 최적화 방법도 있다.

'lr 0.1은 부족하고 5.0은 발산'은 모든 데이터에서 성립하는 법칙이 아니다.

'임계값을 내리면 헛경보가 늘어난다'는 정확히는 늘거나 그대로라는 뜻이다.
같은 확률에서 기준을 내리면 놓침은 줄거나 그대로, 헛경보는 늘거나 그대로다.
정밀도는 보통 낮아질 수 있지만 매번 반드시 낮아지는 것은 아니다.

'공구마모 가중치가 크다'는 이 모델이 활용하는 방향과 크기에 대한 설명이다.
실제 고장 원인이나 미래의 모든 설비에 적용되는 법칙으로 단정할 수 없다.

39) 스스로 설명해보는 확인 문제

질문: 02와 03에서 입력 재료는 같은데 무엇을 맞히는 일이 달라졌을까?
답: 02는 공정온도를, 03은 고장인지 정상인지를 맞힌다.

질문: 시그모이드는 왜 필요할까?
답: 가중치를 곱하고 더한 숫자 점수를 0과 1 사이로 바꿔 확률로 사용하기 위해서다.

질문: 정확도가 98.3%면 고장도 98.3% 찾았다는 뜻일까?
답: 아니다. 이번에는 실제 고장 2개 중 1개만 찾아 재현율은 50%였다.

질문: 정밀도 100%와 재현율 100%는 어떻게 다를까?
답: 정밀도 100%는 낸 경보가 모두 진짜였다는 뜻이고,
재현율 100%는 실제 고장을 모두 찾아냈다는 뜻이다. 각각 분모가 있어야 계산할 수 있다.

질문: 임계값을 바꾸면 w와 b를 다시 구할까?
답: 아니다. 같은 확률을 두고 최종 판정을 나누는 기준만 바꾼다.

질문: 왜 로그손실과 정확도를 따로 계산할까?
답: 로그손실은 확률이 실제 정답에 얼마나 맞는지 보며 학습할 때 쓰고,
정확도는 기준선을 적용한 최종 판정이 몇 개 맞았는지 평가할 때 쓴다.
