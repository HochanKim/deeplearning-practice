04 사이킷런 코드 해설

직접 만들었던 예측 도구를 사이킷런으로 사용하는 방법을 익히는 복습 자료입니다.
01부터 03까지 배운 입력과 정답, 표준화, 학습, 예측, 채점이 그대로 이어집니다.
먼저 만들기 → 학습하기 → 예측하기를 이해하고, 그다음 Pipeline과 교차검증을 읽어보세요.

1) 이번 파일은 무엇을 배우는 걸까

01~03에서는 예측, 손실, 기울기, 가중치 수정 함수를 직접 만들었다.
04에서는 다른 사람들이 미리 만들어 놓은 도구를 가져와 같은 종류의 일을 한다.
그 도구 상자의 이름이 사이킷런(scikit-learn)이다.

손으로 긴 곱셈을 배운 다음 계산기를 쓰는 것과 비슷하다.
계산기가 계산을 대신해도 어떤 숫자를 넣고 결과를 어떻게 읽을지는 사람이 알아야 한다.
파일 제목의 '한 줄로'는 학습 호출이 짧아진다는 뜻이다.
데이터 준비부터 평가까지 모든 일이 진짜 한 줄로 끝난다는 뜻은 아니다.

2) 먼저 기억할 세 가지 동작

model = LinearRegression()  # 예측 도구 만들기
model.fit(X, y)             # 입력과 실제 정답으로 배우기
model.predict(새로운_X)     # 배운 규칙으로 새 답 만들기

만들기: 아직 배우지 않은 도구를 준비한다.
fit: 입력과 정답의 관계에 맞게 모델을 조정한다.
predict: 이미 배운 모델로 예측한다. 정답은 넣지 않는다.

model은 사람이 붙인 변수 이름이다. reg나 clf로 바꿔도 된다.
점(.) 뒤의 fit, predict는 그 도구가 할 수 있는 일인 메서드다.

3) 준비 코드는 앞 파일과 같다

os는 파일 위치, NumPy는 숫자 배열, pandas는 표를 다루는 도구다.
DATA는 데이터 폴더의 위치이고 pd.read_csv는 CSV를 읽어 df에 담는다.
__file__은 실행하는 코드 파일을 가리킨다.
abspath는 전체 경로, dirname은 폴더, '..'는 한 단계 위 폴더다.
os.path.join은 경로 조각들을 연결한다.

특징이름 = ['공기온도', '회전수', '토크', '공구마모']

앞에서 쓰던 네 가지 예측 재료를 목록으로 저장한다.
이번에도 11_설비센서_ai4i.csv를 사용한다.

4) from과 import는 도구 상자에서 필요한 도구를 꺼내는 문법이다

from sklearn.linear_model import LinearRegression

sklearn은 코드에서 사용하는 사이킷런의 이름이다.
linear_model이라는 칸에서 LinearRegression이라는 도구를 가져온다는 뜻이다.
LinearRegression은 앞에서 배운 선형회귀 도구다.
괄호를 붙여 LinearRegression()이라고 쓰면 실제로 사용할 모델 하나를 만든다.

5) 입력 하나도 표 모양으로 넣어야 한다

x = df['공기온도'].values
y = df['공정온도'].values
X1 = x.reshape(-1, 1)

x는 공기온도 200개가 들어 있는 1차원 배열이다. 모양은 (200,)이다.
사이킷런의 이 모델은 입력 X를 '행은 사례, 열은 특징'인 표로 받는다.
그래서 reshape로 (200, 1), 즉 200행 1열 모양으로 바꾼다.

변경 전: [300, 302, 299]
변경 후: [[300], [302], [299]]

숫자는 그대로이고 담는 모양만 바뀐다.
reshape(-1, 1)의 1은 열을 하나로 만들라는 뜻이다.
-1은 전체 숫자 개수에 맞게 행 개수를 알아서 계산하라는 뜻이다.
정답 y는 이번처럼 숫자 하나씩인 경우 (200,) 모양을 그대로 쓴다.

6) fit 한 줄은 무엇을 대신할까

model = LinearRegression()
model.fit(X1, y)

입력 공기온도로 실제 공정온도를 잘 맞히는 w와 b를 구한다.
01에서 손실을 계산하고 w와 b를 여러 번 고쳤던 목적과 같다.
다만 이 LinearRegression은 01의 경사하강 반복문을 그대로 실행하는 것이 아니다.
현재처럼 일반적인 숫자 표에서는 최소제곱 문제를 푸는 수치 계산 방법을 사용한다.
같은 목적을 이루는 도구이지 내부 계산 과정까지 똑같은 복사본은 아니다.

7) 배운 가중치와 절편은 어디에 있을까

model.coef_       → 배운 가중치 w들의 모음
model.intercept_  → 배운 절편 b

입력이 공기온도 하나이므로 model.coef_[0]으로 첫 가중치를 꺼낸다.
실행 결과 w는 약 0.9840, b는 약 14.7799였다.
따라서 예측식은 약 0.9840 × 공기온도 + 14.7799다.

coef_와 intercept_ 끝의 밑줄은 '학습 뒤 얻은 값'이라는 사이킷런의 이름 짓기 관례다.
밑줄 자체가 학습을 실행하는 특별한 문법은 아니다.

8) 새 값도 대괄호 두 겹으로 준다

model.predict([[300.0]])[0]

[[300.0]]은 사례 1개에 특징 1개인 1행 1열 표다.
predict의 결과는 예측값이 담긴 배열이므로 [0]으로 첫 값을 꺼낸다.
예측 공정온도는 약 309.97이었다.
round(값, 2)는 소수점 아래 두 자리로 반올림한다.

model.score(X1, y)는 이 선형회귀 모델의 R²를 계산한다.
값은 약 0.7989였다. 79.89%의 문제를 맞혔다는 정답률은 아니다.
이 첫 시연은 200개로 배우고 같은 200개로 평가하므로 학습 점수다.
새 데이터에 대한 실력 확인은 다음의 학습용·시험용 분리에서 한다.

9) 일부러 오류를 내는 코드는 무엇일까

try:
    LinearRegression().fit(x, y)
except ValueError as e:
    print(str(e).splitlines()[0])

try는 이 일을 해보라는 뜻이다.
except ValueError는 값이나 모양 때문에 해당 오류가 나면 아래 일을 하라는 뜻이다.
e에는 오류 정보가 들어간다.
str(e)는 오류를 글자로 바꾸고 splitlines()는 줄별로 나누며 [0]은 첫 줄이다.

여기서는 표가 아닌 1차원 x를 줘서 오류가 나는 모습을 일부러 보여준다.
오류를 잡아서 설명을 출력하므로 프로그램이 다음 부분으로 계속 진행한다.
앞에서 만든 정상적인 model이 망가졌다는 뜻은 아니다.

10) train_test_split은 짝을 유지하며 데이터를 나눈다

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42
)

X는 센서 열 4개를 꺼낸 입력 표이고 y는 공정온도 정답이다.
test_size=0.3은 시험용으로 30%를 쓰겠다는 뜻이다.
random_state=42는 실행할 때 같은 분할을 재현하기 위한 번호다.
도구가 기본적으로 섞은 뒤 입력과 정답의 짝을 유지하며 나눈다.

학습용 X: (140, 4) / 시험용 X: (60, 4).
02와 같은 42를 써도 번호를 나누는 방식이 달라 같은 사례가 뽑히지는 않는다.
그래서 02의 점수와 이번 점수가 조금 달라도 이상한 것이 아니다.

11) StandardScaler는 표준화 담당 도구다

scaler = StandardScaler()
scaler.fit(X_train)
Z_train = scaler.transform(X_train)
Z_test = scaler.transform(X_test)

scaler.fit은 학습용 각 열의 평균과 표준편차를 알아두는 일이다.
transform은 알아둔 눈금으로 실제 값을 바꾸는 일이다.
공식은 앞에서 쓴 (값 - 평균) / 표준편차다.

모델의 fit: 입력과 정답으로 예측 규칙을 배운다.
스케일러의 fit: 입력에서 눈금에 필요한 통계를 구한다.
둘 다 '이 도구가 사용할 정보를 데이터에서 정한다'는 공통점이 있다.

시험용은 transform만 한다. fit을 다시 하면 시험용 눈금으로 바뀌어 버린다.
scaler.mean_은 학습용 평균이고 scaler.scale_은 변환에 쓰는 나눗셈 눈금이다.
표준편차가 0인 열은 StandardScaler가 나누기 눈금을 1로 처리한다.
공식 설명: https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.StandardScaler.html

12) 여러 센서로 배우는 것도 같은 fit이다

reg = LinearRegression().fit(Z_train, y_train)

모델을 만들고 바로 학습시키는 것을 한 문장으로 연결했다.
fit은 학습한 모델 자신을 돌려주므로 reg에 그 모델을 담을 수 있다.

reg = LinearRegression()
reg.fit(Z_train, y_train)

이 두 줄로 풀어 써도 같은 의미다.
이번에는 열이 네 개이므로 reg.coef_에 가중치 네 개가 들어간다.
학습용 R²는 0.8155, 시험용 R²는 0.7425였다.

13) 가중치를 보기 좋게 출력하는 문법

dict(zip(특징이름, reg.coef_.round(3).tolist()))

.round(3)은 소수점 아래 세 자리로 반올림한다.
.tolist()는 NumPy 배열을 파이썬 리스트로 바꾼다.
zip은 특징 이름과 해당 가중치를 순서대로 짝짓는다.
dict는 그 쌍들을 '이름: 값' 형태의 사전으로 만든다.

예: {'공기온도': 1.986, '회전수': 0.004, ...}
가중치의 계산 원리를 바꾸는 것이 아니라 출력에 이름표를 붙이는 과정이다.

14) Pipeline은 여러 도구를 순서대로 연결한 작업 줄이다

pipe = make_pipeline(StandardScaler(), LinearRegression())

왼쪽의 표준화 도구 다음에 오른쪽의 선형회귀 모델을 연결한다.
공장 작업대처럼 원래 입력 → 표준화 → 예측 모델 순서로 움직인다.

pipe.fit(X_train, y_train)

안에서 학습용 눈금을 만들고, 학습용을 변환하고, 모델까지 학습한다.
pipe.predict(X_test)는 이미 학습한 눈금으로 시험용을 변환한 뒤 예측한다.
예측할 때 평균과 표준편차를 다시 배우지 않는다.

15) Pipeline에는 원래 눈금의 X를 넣는다

pipe.predict([[300, 1500, 40, 100]])

표준화를 파이프라인이 담당하므로 직접 Z로 바꿔 넣지 않는다.
이미 표준화한 값을 다시 넣으면 원래 센서값인 줄 알고 또 변환할 수 있다.
새 입력 열의 순서는 반드시 공기온도, 회전수, 토크, 공구마모다.
모두 숫자라 하더라도 순서를 바꾸면 다른 센서로 해석한다.

새 사례의 예측 공정온도는 약 310.03이었다.
pipe의 시험용 R²는 0.7425로 앞에서 따로 표준화한 결과와 같았다.

16) Pipeline이 모든 잘못을 자동으로 막는 것은 아니다

학습용만 fit에 넣으면 표준화도 학습용에서 배운다.
교차검증에서도 각 학습 조각 안에서 표준화를 배우도록 묶을 수 있다.
하지만 전체 데이터로 pipe.fit을 해버리면 시험 정보도 함께 배우게 된다.
중복 기록이나 잘못된 정답도 이 Pipeline이 자동으로 청소해주지 않는다.
다음 실험은 그중 중복 기록 문제를 보여준다.

17) 이웃 한 명의 답을 참고하는 모델

KNeighborsRegressor(n_neighbors=1)

새 입력과 가장 가까운 학습 사례 하나를 찾아 그 사례의 정답으로 예측한다.
비슷한 문제를 먼저 풀었던 친구 한 명의 답을 참고하는 느낌이다.
가까운 정도를 숫자로 재므로 센서의 눈금을 맞추는 표준화도 함께 사용한다.

이웃 = lambda: make_pipeline(StandardScaler(), KNeighborsRegressor(n_neighbors=1))

lambda: 뒤의 일을 실행하는 짧은 함수를 만든다.
이웃()을 부를 때마다 새 파이프라인을 하나 만든다.
다음처럼 풀어 읽을 수 있다.

def 이웃():
    return make_pipeline(StandardScaler(), KNeighborsRegressor(n_neighbors=1))

18) 일부러 데이터를 두 장씩 복사하는 이유

X중복 = np.vstack([X, X])
y중복 = np.concatenate([y, y])

vstack은 입력 표를 위아래로 쌓는다. (200, 4)가 (400, 4)가 된다.
concatenate는 정답 배열을 이어 붙인다. 정답도 400개가 된다.
복사한 문제와 답을 함께 붙였으므로 짝은 유지된다.

이 상태에서 무작위로 나누면 어떤 원본은 학습용에, 그 복사본은 시험용에 들어간다.
한 이웃 모델은 시험 문제와 똑같은 학습 사례를 만나 정답을 바로 찾을 수 있다.
새 문제를 푼 줄 알았는데 이미 본 문제의 복사본이었던 것이다. 이것이 누수다.

19) 중복 때문에 점수가 높아지는 모습을 읽자

복사본을 섞어 나눈 시험 R²: 0.8177
원본만 나눈 시험 R²:       0.1864

점수가 좋아 보이는 이유가 새 사례를 잘 이해해서가 아닐 수 있음을 보여준다.
R²를 보고 '실력이 네 배 좋아졌다'고 해석하면 안 된다.
원본만 나눈 점수도 이번 분할에서 얻은 평가이지 영원히 고정된 진짜 실력은 아니다.

실제로 같은 측정 기록이 중복 저장됐으면 정리하고 나누는 것이 필요하다.
센서값이 우연히 같은 별개의 측정까지 무조건 지우라는 뜻은 아니다.
같은 설비나 같은 원본에서 나온 기록끼리 묶어서 분할해야 하는 경우도 있다.

20) 이제 정답을 고장여부로 바꾸어 분류한다

yc = df['고장여부'].values

y는 앞의 공정온도 정답, yc는 이번 고장여부 정답이다.
변수 이름을 나눠서 뒤에서 회귀와 분류를 각각 이어갈 수 있게 했다.
yc의 c는 분류를 구별하려고 붙인 이름일 뿐 특별한 문법은 아니다.

train_test_split(X, yc, test_size=0.3, random_state=3, stratify=yc)

stratify=yc는 정상과 고장 비율을 고려해서 양쪽에 나누라는 뜻이다.
고장이 적어서 시험용에 고장이 빠지는 문제를 줄이려는 것이다.
이번에는 학습용 고장 6개, 시험용 고장 2개였다.
정수 개수로 나누므로 비율이 항상 정확히 같아지는 것은 아니다.

21) 로지스틱 회귀도 파이프라인으로 만든다

clf = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
clf.fit(Xc_train, yc_train)

03의 표준화 → 점수 → 시그모이드 → 확률 → 손실을 줄이는 학습을 도구로 맡긴다.
clf는 분류 모델을 담은 변수 이름이다.
max_iter=1000은 최적화 계산의 최대 반복 횟수다.
충분히 계산되면 더 일찍 멈출 수 있다. 반드시 1000번 반복하라는 뜻은 아니다.

03과 정확히 같은 결과를 기대하면 안 된다.
나눠진 사례가 다르고, 기본 LogisticRegression에는 규제가 있으며,
기본 최적화 방법도 03의 수치미분 경사하강 반복문과 다르다.
같은 종류의 모델을 더 편리한 도구로 배우는 것이라고 이해하자.
공식 설명: https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html

22) predict_proba와 predict는 결과가 다르다

clf.predict_proba(Xc_test) → 각 종류일 확률을 담은 표
clf.predict(Xc_test)       → 최종 종류인 0 또는 1

여기서 확률 표는 60행 2열이다.
예를 들어 [0.8, 0.2]는 정상 확률 80%, 고장 확률 20%다.
열의 순서는 모델의 classes_에 따른다. 이번 정답 0과 1에서는 [0, 1] 순서다.

p = clf.predict_proba(Xc_test)[:, 1]

:는 모든 행, 1은 두 번째 열이다. 따라서 모든 사례의 고장 확률만 꺼낸다.
p의 모양은 (60,)이다.
이진 분류 predict는 기본적으로 0.5를 경계로 생각하면 된다.
다만 정확히 확률이 같은 경계에서는 직접 쓴 >= 0.5와 동률 처리 결과가 다를 수 있다.

23) 높은 확률만 골라 출력한다

np.sort(p)[::-1][:5].round(3)

np.sort(p)는 확률 숫자를 작은 순서대로 정렬한다.
[::-1]은 그 순서를 뒤집는다.
[:5]는 앞의 다섯 개만 꺼낸다.
.round(3)은 소수점 아래 세 자리로 표시할 숫자를 만든다.

03의 argsort는 정렬할 위치 번호를 돌려줬다.
여기의 sort는 정렬한 값 자체를 돌려준다는 차이가 있다.
이번 상위 확률은 약 [0.366, 0.348, 0.243, 0.240, 0.234]였다.
전부 0.5보다 낮아서 기본 판정은 시험용 전체에 정상이라고 답했다.

24) score가 항상 같은 채점법인 것은 아니다

reg.score(...) → 이번 회귀 모델에서는 R²
clf.score(...) → 이번 분류 모델에서는 정확도

메서드 이름은 같지만 모델 종류에 따라 기본 점수가 다르다.
이번 분류 정확도는 약 0.967이었다.
정상 58개는 맞히고 고장 2개는 전부 놓쳐도 58 / 60 = 96.7%다.
03에서 배운 정확도의 함정이 도구를 사용해도 사라지지 않는다.

25) 혼동행렬의 네 칸 위치를 확인하자

confusion_matrix(yc_test, 판정)

첫 번째 입력은 실제 정답, 두 번째 입력은 모델 판정이다.
이번 0과 1 순서에서는 행이 실제, 열이 판정이다.

                  정상 판정    고장 판정
실제 정상           TN           FP
실제 고장           FN           TP

실제 출력은 [[58, 0], [2, 0]]이었다.
정상 통과 58개, 헛경보 0개, 놓친 고장 2개, 찾은 고장 0개다.

tn, fp, fn, tp = confusion_matrix(yc_test, 판정).ravel()

ravel()은 표를 한 줄로 펴서 [58, 0, 2, 0]으로 만든다.
그 순서대로 네 변수에 담는다.
03의 네칸 함수가 돌려주던 TP, FN, FP, TN 순서와 다르므로 주의하자.

26) classification_report는 여러 채점 결과를 모은 성적표다

classification_report(yc_test, 판정, target_names=['정상', '고장'], zero_division=0)

target_names는 출력할 종류 이름이다.
precision은 정밀도: 해당 종류라고 한 것 중 실제로 맞은 비율.
recall은 재현율: 실제 해당 종류 중 찾아낸 비율.
f1-score는 정밀도와 재현율을 함께 보는 점수다.
계산은 2 × 정밀도 × 재현율 / (정밀도 + 재현율)이다.
support는 실제로 그 종류인 사례 수다. 이번 고장의 support는 2다.

정상 행은 정상을 찾는 관점이고 고장 행은 고장을 찾는 관점이다.
고장을 놓치는지 궁금하면 고장 행을 읽어야 한다.
macro avg는 종류별 점수를 똑같은 비중으로 평균 낸 값이다.
weighted avg는 사례가 많은 종류에 더 큰 비중을 준 평균이다.
정상이 많은 데이터에서는 weighted avg가 높아도 고장 점수는 낮을 수 있다.

zero_division=0은 분모가 없어 정의할 수 없는 점수를 0으로 표시하라는 설정이다.
이번에는 고장 경보를 하나도 안 냈으므로 고장 정밀도를 나눗셈으로 정의할 수 없다.
출력의 0은 그 경우 대신 표시한 값이다.

27) 임계값을 내리는 실험도 도구로 채점한다

판정_th = (p >= th).astype(int)
recall_score(yc_test, 판정_th, zero_division=0)
precision_score(yc_test, 판정_th, zero_division=0)

기존 확률 p는 그대로 두고, 어느 확률부터 경보를 울릴지만 바꾼다.
이 두 채점 함수는 여기서 기본적으로 1인 고장을 찾는 점수를 계산한다.

임계값 0.5 → 재현율 0.00 / 정밀도 0.00
임계값 0.3 → 재현율 0.00 / 정밀도 0.00
임계값 0.2 → 재현율 0.50 / 정밀도 0.20
임계값 0.1 → 재현율 1.00 / 정밀도 약 0.17

0.1에서는 고장을 모두 찾았지만 경보 중 정상도 많았다.
03과 숫자가 다른 것은 분할과 학습 설정 등이 다르기 때문이다.
임계값을 바꾸는 이 단계에서는 모델을 다시 학습하지 않는다.

28) class_weight balanced는 학습할 때 드문 종류에 더 큰 비중을 준다

LogisticRegression(max_iter=1000, class_weight='balanced')

정상 문제가 매우 많으면 정상들을 맞히는 쪽이 학습에 큰 영향을 줄 수 있다.
balanced는 드문 고장 사례 하나의 손실에 더 큰 비중을 준다.
'드문 고장 문제도 중요하게 채점해 줘'라는 설정이다.
고장 데이터를 실제로 복사해서 개수를 늘리는 명령은 아니다.

clf_b.fit(Xc_train, yc_train)

학습 규칙의 비중이 바뀌므로 새로 학습해서 새로운 w와 b를 얻는다.
이번에는 기본 판정 기준에서 재현율 1.00, 정밀도 약 0.15였다.
고장을 모두 찾는 대신 헛경보가 많아졌다.
balanced를 쓴다고 언제나 좋은 결과가 보장되지는 않는다.

임계값 변경: 배운 모델은 그대로, 판정 기준만 바꾼다.
class_weight 변경: 학습의 벌점 비중을 바꾸고 모델을 다시 배운다.

29) Ridge는 가중치를 너무 크게 만드는 데 벌점을 더한다

Ridge(alpha=a)

02의 과적합을 떠올려보자. 연습 데이터의 우연까지 맞추려다 새 문제에서 약해질 수 있었다.
Ridge는 예측 오차와 함께 가중치 크기도 고려해서 학습한다.
큰 가중치에 벌점을 주는 방법을 규제라고 부른다.
벌점에는 가중치 제곱들의 합이 사용된다.

alpha는 그 벌점을 얼마나 중요하게 볼지 정하는 설정이다.
작으면 기존 선형회귀에 가깝고, 크면 가중치를 더 강하게 줄이는 방향으로 학습한다.
alpha는 학습률이 아니다. 걷는 보폭이 아니라 어떤 답을 선호할지 정하는 값이다.
입력 눈금이 다르면 가중치 크기의 의미도 달라지므로 앞에 표준화를 둔다.

30) 규제가 강할수록 무조건 좋을까

현재 센서 네 개로 얻은 R²:
alpha 0.01 → 학습 0.8155 / 시험 0.7425
alpha 1    → 학습 0.8155 / 시험 0.7438
alpha 10   → 학습 0.8116 / 시험 0.7500
alpha 100  → 학습 0.6763 / 시험 0.6357

이번에는 10에서 시험 점수가 조금 좋아졌지만 100에서는 양쪽 모두 낮아졌다.
벌점이 너무 강하면 필요한 관계까지 약하게 배우기 때문이다.
따라서 '과적합이 걱정되니 alpha를 무조건 크게'는 답이 아니다.
얼마가 적당한지는 뒤에서 교차검증으로 고른다.

31) PolynomialFeatures는 기존 재료를 곱해서 새 특징을 만든다

PolynomialFeatures(4)

괄호의 4는 네 센서를 고르라는 뜻이 아니라 최대 4차까지 만들라는 뜻이다.
예를 들어 입력이 a와 b이면 a, b 외에 a², a×b, b² 같은 특징을 만들 수 있다.
4차이면 a⁴이나 a²×b² 같은 조합까지 포함할 수 있다.

현재 입력 네 개에서는 상수 1 열까지 포함하여 70개 열이 만들어진다.
측정을 새로 66개 한 것이 아니다. 같은 네 센서값에서 계산 재료를 더 만든 것이다.
모델은 이런 특징에 가중치를 붙여 원래 센서값의 더 복잡한 관계를 표현할 수 있다.
하지만 표현이 복잡해지면 연습 데이터의 우연까지 맞출 가능성도 커진다.

32) 다항식 Pipeline에 표준화가 두 번 있는 이유

make_pipeline(StandardScaler(), PolynomialFeatures(4), StandardScaler(), 모델)

첫 표준화: 원래 큰 센서값을 그대로 높은 제곱으로 키우지 않게 눈금을 맞춘다.
특징 생성: 표준화한 센서값에서 제곱과 곱셈 조합을 만든다.
둘째 표준화: 새로 만든 특징들의 크기와 퍼짐이 다시 다르므로 눈금을 맞춘다.
마지막 모델: 그 특징으로 공정온도를 예측하도록 학습한다.
새 입력을 예측할 때도 같은 순서와 이미 학습한 눈금을 쓴다.

이번 실험 결과:
규제 없음 → 학습 R² 0.892 / 시험 R² 0.430
Ridge 10  → 학습 R² 0.869 / 시험 R² 0.649

Ridge가 연습 점수는 낮췄지만 시험 점수는 높였다.
그러나 단순한 네 특징 모델의 시험 점수 0.7425보다 낮다.
복잡한 특징을 만들고 규제까지 썼다고 항상 단순한 모델보다 좋아지는 것은 아니다.

33) w와 alpha는 누가 정하는 값일까

w와 b: fit이 학습 데이터에서 구하는 값. 모델의 파라미터다.
alpha: 학습 방법의 설정. 사람이 정하거나 후보 중 고른다. 하이퍼파라미터라고 한다.

학생이 공부해서 얻은 실력이 w와 b라면,
공부 방법을 정하는 설정에 가까운 것이 alpha다.
설정까지 시험 점수를 계속 보며 고르면 마지막 시험이 공정한 평가 역할을 잃는다.
그래서 시험용을 남겨놓고 학습용 안에서 설정을 비교한다.

34) 교차검증은 학습용 안에서 돌아가며 모의시험을 보는 것이다

cross_val_score(make_pipeline(StandardScaler(), LinearRegression()),
                X_train, y_train, cv=5)

학습용 140개를 다섯 조각 A, B, C, D, E로 나눈다.
첫 번째: B C D E로 배우고 A로 채점.
두 번째: A C D E로 배우고 B로 채점.
이렇게 각 조각이 한 번씩 채점용이 되도록 다섯 번 반복한다.
이번에는 매번 112개로 배우고 28개로 채점한다.
바깥에 보관한 시험용 60개는 여기에 들어가지 않는다.

각 반복은 새로 학습하는 모델이다. 하나를 계속 이어서 훈련하는 것이 아니다.
파이프라인 안에 스케일러가 있어 각 반복의 학습 112개로만 눈금을 만든다.
미리 전체 140개를 표준화해서 교차검증에 넣으면 채점 조각 정보가 눈금에 섞인다.

35) 교차검증 결과를 읽어보자

cv는 여기서 점수 다섯 개를 담은 배열이다.
실행 결과 약 [0.723, 0.848, 0.846, 0.710, 0.824]였고 평균은 0.7901이었다.
이번 회귀 모델에서는 기본 평가 점수가 R²다.
조각마다 결과가 다르므로 한 번의 작은 시험만으로 판단하기 어렵다는 것도 보여준다.

cv=5라고만 준 현재 회귀 코드의 기본 분할은 새로 무작위로 섞는 방식이 아니다.
앞에서 만들어진 학습용 순서를 다섯 부분으로 나누어 사용한다.
시간에 따라 예측하는 문제나 같은 설비의 반복 기록에는 적절한 별도 분할이 필요할 수 있다.

36) GridSearchCV는 후보 설정을 하나씩 시험하는 도구다

grid = GridSearchCV(
    make_pipeline(StandardScaler(), Ridge()),
    {'ridge__alpha': [0.01, 0.1, 1, 10, 100]},
    cv=5
)
grid.fit(X_train, y_train)

그리드 검색은 후보 설정들을 정해두고 하나씩 비교하는 방식이다.
이번에는 alpha 후보가 다섯 개이고 각 후보마다 다섯 번 교차검증한다.
후보 비교에 5 × 5 = 25번 학습이 필요하다.
그 뒤 기본 설정으로는 가장 좋은 후보를 골라 학습용 140개 전체로 한 번 더 학습한다.
따라서 마지막 재학습까지 세면 모델 학습은 총 26번이다.

'ridge__alpha'는 Pipeline 안의 ridge 단계에 있는 alpha 설정을 가리킨다.
가운데 밑줄 두 개 __는 단계 이름과 설정 이름을 연결하는 사이킷런 규칙이다.
학습된 값 이름 끝의 밑줄 하나 _와 구별하자.
공식 설명: https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GridSearchCV.html

37) 가장 좋은 후보를 고른 뒤에 시험용으로 확인한다

grid.best_params_ → 교차검증으로 고른 설정
grid.best_score_  → 그 설정의 교차검증 평균 점수
grid.score(X_test, y_test) → 최종 모델의 시험용 점수

이번에는 alpha=1이 선택됐고 교차검증 평균 R²는 0.7904였다.
선택된 설정으로 전체 학습용에 다시 학습한 모델의 시험 R²는 0.7438이었다.
앞의 시연에서 시험 점수만 보면 alpha=10이 높았는데 왜 1을 골랐을까?
선택에 시험 점수를 쓰지 않고 교차검증 평균을 썼기 때문이다.

다만 이 수업 파일 전체는 여러 방법의 시험 점수를 이미 출력하는 시연이다.
실제 개발에서는 그 시험 점수들을 보고 설정을 계속 바꾸지 않도록 해야 한다.
가장 높은 시험 점수를 골라놓고 '마지막 한 번 평가'라고 부르면 안 된다.

38) 학습 결과를 파일에 저장한다

joblib.dump(clf, '고장분류기.joblib')
다시 = joblib.load('고장분류기.joblib')

dump는 학습한 도구를 파일로 저장하고 load는 파일에서 다시 불러온다.
저장하는 clf는 표준화 도구와 분류 모델을 함께 가진 Pipeline이다.
학습한 눈금과 모델을 같이 보관하므로 새 입력은 원래 눈금으로 넣으면 된다.

여기서 저장하는 것은 balanced 모델 clf_b가 아니라 기본 분류 모델 clf다.
회귀 모델 grid도 아니다. 변수 이름을 꼭 확인하자.
joblib 파일은 자신이 만들었거나 신뢰할 수 있는 파일만 불러와야 한다.
이 형식은 불러오는 과정에 코드가 실행될 수 있어서 출처가 중요한 파일이다.

39) 불러온 모델로 바로 예측한다

다시.predict_proba([[299, 1400, 55, 240]])[0, 1]

입력은 공기온도, 회전수, 토크, 공구마모 순서다.
결과 확률 표에서 [0, 1]은 첫 사례의 두 번째 열인 고장 확률을 꺼낸다.
현재 실행 결과는 약 0.283이었다. 모델이 추정한 값이지 실제 고장 여부는 아니다.
새로 fit하지 않고 저장했던 학습 결과로 바로 예측한다.

os.remove('고장분류기.joblib')

마지막 줄은 저장한 파일을 지우는 수업용 정리 코드다.
따라서 이 스크립트를 끝까지 실행하면 모델 파일은 남지 않는다.
보관하려면 이 삭제 줄을 실행하지 않아야 한다.
상대 경로로 저장하므로 위치는 코드 파일의 폴더가 아니라 실행 당시 작업 폴더다.

40) 마지막 실습인 Lasso는 무엇이 다를까

Ridge는 가중치 제곱들의 합에 벌점을 준다.
Lasso는 가중치 절댓값들의 합에 벌점을 준다.
Lasso는 학습 결과에서 일부 가중치를 정확히 0으로 만들 수 있다.
그래서 몇몇 특징을 예측식에서 사용하지 않는 효과가 생길 수 있다.
0이 됐다고 실제로 영원히 필요 없는 센서라고 단정할 수는 없다.

현재 04 파일에는 문제와 힌트만 있고 Lasso 실습 실행 코드는 없다.
아래처럼 별도 실습으로 이어서 작성할 수 있다.

from sklearn.linear_model import Lasso

for a in [0.01, 0.1, 1.0]:
    lasso = make_pipeline(StandardScaler(), Lasso(alpha=a))
    lasso.fit(X_train, y_train)
    print(a, lasso.score(X_train, y_train), lasso.score(X_test, y_test))

각 alpha에서 새 모델을 만들고 학습한 뒤 양쪽 점수를 비교한다.
Ridge와 Lasso는 벌점 공식과 크기 기준이 다르므로 같은 alpha가 같은 강도라는 뜻은 아니다.
실제로 설정을 고를 때는 이 시연을 그대로 시험 점수 선택 도구로 쓰지 말고 교차검증을 사용하자.

42) 사이킷런과 파이토치는 언제 쓸까

이번처럼 센서값이 행과 열로 정리된 문제는 사이킷런으로 기본 모델을 만들기 편하다.
파이토치는 신경망을 구성하거나 학습 계산을 더 직접 설계할 때 많이 사용한다.
데이터가 몇 행 이상이면 무조건 파이토치라는 고정된 경계가 있는 것은 아니다.
풀려는 문제와 모델, 계산 자원에 맞춰 도구를 고르는 것이다.

43) 스스로 설명해보는 확인 문제

질문: fit과 predict는 어떻게 다를까?
답: fit은 데이터로 배우는 일이고 predict는 배운 것을 사용해서 답을 만드는 일이다.

질문: 특징이 하나인데 왜 reshape(-1, 1)을 할까?
답: 사이킷런의 입력을 사례 수 × 특징 수의 2차원 표 모양으로 맞추기 위해서다.

질문: Pipeline에 표준화가 들어 있다면 새 입력을 미리 표준화할까?
답: 아니다. 원래 눈금의 값을 주면 안에서 배운 눈금으로 변환한다.

질문: score가 0.9이면 무조건 정확도 90%일까?
답: 아니다. 이번 회귀 모델에서는 R², 분류 모델에서는 정확도다.

질문: alpha가 커지면 더 크게 걷는 걸까?
답: 아니다. alpha는 Ridge나 Lasso에서 가중치 크기에 주는 벌점의 강도다.

질문: 교차검증 다섯 번은 시험용 60개를 다섯 번 보는 걸까?
답: 아니다. 학습용 140개 안에서 학습과 검증 역할을 번갈아 나누는 것이다.

질문: 모델 저장 후에도 평균과 표준편차가 필요할까?
답: 필요하다. 그래서 이번에는 표준화 도구까지 포함한 Pipeline을 저장한다.
